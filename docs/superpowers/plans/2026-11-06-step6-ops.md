# Step 6: Ops (Observability + Failure Handling) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Know when something breaks and be able to fix it: structured JSON logs with correlation ids, alarms on every dead-letter queue and on failed pipeline runs that notify an ops SNS topic, bounded log retention, and an ops CLI (status, break-it-on-purpose, redrive).

**Architecture:** `services/src/lib/log.ts` wraps AWS Lambda Powertools Logger (JSON, service name, cold start, correlation keys). `infra/lib/ops.ts` adds the `<prefix>-ops` SNS topic, one `ApproximateNumberOfMessagesVisible > 0` alarm per DLQ (uploads, fanout, notify), a Step Functions `ExecutionsFailed > 0` alarm, and (local stage only) an `<prefix>-ops-inbox` SQS subscription so scripts can read alarm notifications. Every function gets an explicit log group (2 weeks retention, DESTROY). `scripts/src/ops.ts`: `npm run ops` (DLQ depths + alarm states), `npm run ops chaos` (poison message → DLQ → alarm), `npm run ops redrive <queue>` (move DLQ messages back).

**Tech Stack:** previous + `@aws-lambda-powertools/logger` 2.36.

**Spec:** `docs/superpowers/specs/2026-11-06-instagram-lite-design.md` (Ops row: DLQ alarm → SNS; "break it on purpose").

## Global Constraints
- Alarm names `<prefix>-<queue>-dlq-not-empty`, `<prefix>-pipeline-failed`; actions → ops topic; `treatMissingData: notBreaching`.
- Log groups `/aws/lambda/<prefix>-<name>`, retention 14 days, DESTROY (fixes step-1 deferred minor).
- The ops inbox queue exists only when `isLocal`.
- Docs: `06-ops.md` (+ "How big companies do it"), notes §9 (observability: logs/metrics/traces, alerting on symptoms, runbooks), study list.
