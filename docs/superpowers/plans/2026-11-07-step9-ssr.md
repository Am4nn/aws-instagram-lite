# Step 9: Server-side rendering (OpenNext on Lambda + BFF + cookie auth) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every page is rendered on a Next.js server Lambda (OpenNext) behind the one CloudFront distribution, the browser talks only to that server (BFF), and login lives in httpOnly cookies.

**Architecture:** `@opennextjs/aws` builds `web/.open-next/`; `infra/lib/web.ts` deploys the server bundle as a Lambda with a Function URL (`authType: NONE`) and puts it behind CloudFront as the default behaviour (`CachingDisabled`, `AllViewerExceptHostHeader`, all methods, origin header `x-origin-verify`). `/_next/static/*` → S3 web bucket (OAC), `/media/*` → S3 media bucket (OAC). `web/proxy.ts` rejects requests without the origin secret, sends logged-out page requests to `/bff/auth/refresh` → `/login`, and checks `Origin` + JSON on every `/bff/*` mutation. Server components call the HTTP API with the `ig_id` cookie as Bearer; client islands call `/bff/api/*` (an allowlisted forwarder).

**Tech Stack:** previous + `@opennextjs/aws` 4.1.15 (wrapper `aws-lambda`, converter `aws-apigw-v2`, dummy caches), Next 16.4.5 `proxy.ts`, vitest in `web/`.

**Spec:** `docs/superpowers/specs/2026-11-07-step9-ssr-design.md` (incl. "Spike results").

## Global Constraints
- `@opennextjs/aws` 4.1.x, next stays 16.4.5. No streaming, ISR, revalidation queue, tag cache, image optimization (`images.unoptimized`), Lambda@Edge or warmer.
- Server Lambda: Node 22, 1024 MB, Function URL `authType: NONE`; CloudFront adds `x-origin-verify: <secret>`; `proxy.ts` 403s without it; check skipped only when `ORIGIN_VERIFY_SECRET` is unset (`next dev`).
- Cookies: `ig_id` = ID token, `HttpOnly; SameSite=Lax; Path=/; Max-Age=<token life>`, `Secure` on aws only. `ig_refresh` = refresh token, `HttpOnly; SameSite=Lax; Path=/bff/auth; Max-Age=30 days`, `Secure` on aws only.
- Every non-GET `/bff/*`: `Origin` must equal the site origin and `content-type` must be `application/json`, else 403 / 415.
- No token readable by JS, no credential in a URL, no `localStorage` token code left.
- Routes `/p/[id]` (`?u=<author>` hint kept), `/u/[name]`; `/p?id=…&u=…` and `/u?name=…` redirect.
- Photos: APIs return `/media/<key>`; uploads still browser → S3 presigned PUT; uploads CORS = site origins on aws.
- HTTP API routes + JWT authorizer unchanged; CORS removed.
- Floci: `deploy:web` writes `SSR_ORIGIN_HOST=<id>.lambda-url.us-east-1.localhost.floci.io` into `.env` and recreates the container only when `.env` changed. Local origin = that host, port 4566, http-only.
- UI looks exactly as before (same components and CSS).
- Never run anything against real AWS. One `next build`/dev server at a time.

## Review Focus
1. Expired `ig_id` on a page load → refresh via `/bff/auth/refresh?next=<path>` and come back, not a logout → pinned in Task 2 (`safeNext`, proxy decision tests) and Task 7 smoke (refresh POST).
2. Open redirect via `next=` (`//evil.com`, `https://evil.com`) → falls back to `/feed` → Task 2 `safeNext` test.
3. A `/bff/api` path outside the allowlist (e.g. `PUT /posts/x`, `../health`) → 404, never forwarded → Task 2 `matchForward` test.
4. Cross-site POST (wrong/missing `Origin`, `text/plain` form body) → 403/415 → Task 2 `checkMutation` tests + Task 7 smoke.
5. Direct Function URL hit without/with wrong `x-origin-verify` → 403 → Task 2 test + Task 7 smoke.

## Rulings ledger (builder decisions; cost if wrong)
| # | Ruling | Cost if wrong |
|---|---|---|
| R1 | Floci path-pattern behaviours verified by a throwaway 2-origin distribution (`/media/*` routed to the media bucket): they work, no local fallback needed. | none known |
| R2 | Origin secret = the UUID part of `AWS::StackId` (random per stack, stable, no extra resource), passed to CloudFront origin header + Lambda env. | Anyone with CloudFormation read can see it (same people who can read Lambda env). Rotate = new stack. |
| R3 | `ig_refresh` is path-scoped to `/bff/auth`, so `proxy.ts` can't read it on `/feed`: a missing/expiring `ig_id` redirects to `GET /bff/auth/refresh?next=<path>`, which refreshes and redirects back, or to `/login`. Logged-out `/feed` = 2 hops to `/login`. Client fetches that get 401 call `POST /bff/auth/refresh` once and retry. | One extra redirect for logged-out users. |
| R4 | Site origin for the CSRF check = `x-forwarded-host` (set by a CloudFront Function on viewer-request, the SST/OpenNext pattern) or `host`, plus proto, plus the static `SITE_ORIGINS` env (custom domain). Redirects use relative `Location`. | If Floci forwards neither, local CSRF check needs the env fallback (recorded in floci-compat). |
| R5 | One allowlisted forwarder `app/bff/api/[...path]/route.ts` instead of one file per action; the client `api()` keeps its signature, so islands change little. | Allowlist must track new API routes. |
| R6 | API CORS removed on both stages (no browser calls it anywhere now), and the Lambdas stop sending `access-control-allow-origin: *`. | A forgotten browser call to the API fails (smoke covers every flow). |
| R7 | Dev-only env goes to `web/.env.development.local` (Next loads it only in `next dev`); old `web/.env.local` is deleted so no localhost value can be bundled into the Lambda. Lambda env sets every var explicitly. | `next dev` users must re-run `deploy:local` once. |
| R8 | No `loading.tsx`: with a buffered (non-streaming) response it would only add a hidden fallback to the HTML. Client-side loads (load more, comments) keep the existing skeleton/spinner. | Link navigations show no skeleton while the server renders (~100-300 ms warm). |
| R9 | `SIGNUP_EMAIL=required` becomes a server env (aws stage) passed as a prop to the login form. | none |
| R10 | Media objects already carry `Cache-Control: public, max-age=31536000, immutable` (resize step, step 3): nothing to change. | none |
| R11 | Server Lambda bundle is a CDK asset (`web/.open-next/server-functions/default`); if it's missing (fresh clone, unit tests) a tiny inline placeholder answers 503 "run npm run deploy:web". `deploy:web`/`deploy:aws` build first, then `cdk deploy`. | none |
| R12 | Server Lambda joins the ops dashboard and gets an explicit log group (`/ig/<prefix>/web-server`). Lambda count: 17 Floci / 16 AWS. | none |
| R13 | No compression on the default behaviour (CachingDisabled can't gzip; OpenNext's plain `aws-lambda` wrapper doesn't either). | Pages travel uncompressed (~40-60 KB). Upgrade: `aws-lambda-compressed` wrapper. |
| R14 | Asset publish keeps old hashed chunks under `_next/static/` (only non-hashed leftovers like the step 7 HTML are deleted). | The web bucket grows a little per deploy (KBs). |
| R15 | (found in Task 7) Floci's CloudFormation drops CloudFront `AllowedMethods`/`CachePolicyId`/`OriginRequestPolicyId`: `scripts/src/floci-cdn.ts` copies them from the synthesized template via the CloudFront API after every local deploy. | Local only; aws untouched. |
| R16 | (found in Task 7) Floci drops `[...path]` folders from Lambda zips: the BFF forwarder is mounted at `[a]`, `[a]/[b]`, `[a]/[b]/[c]` (max API depth is 3 segments). | A 4-segment API route would need one more folder. |
| R17 | (found in Task 7) No CloudFront Functions on Floci, so no `x-forwarded-host`: local deploys pass `-c localSiteOrigin=<local CloudFront URL>` (from the previous deploy's outputs) into `SITE_ORIGINS`. First-ever `deploy:local` lacks it; `deploy:web` adds it. | Local CSRF check fails until `deploy:web` has run once. |
| R18 | Proxy redirects use `new URL(path, req.url)`; OpenNext rewrites same-origin Locations to relative ones, so the browser stays on its own host. Route-handler redirects are relative. | none |
| R19 | `/media/*` excluded from the proxy matcher (CloudFront serves it from S3; in `next dev` a rewrite to Floci S3 serves it). | none |
